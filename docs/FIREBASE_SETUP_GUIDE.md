## Firebase Console Setup

### Step 1: Create Firebase Project

1. Go to [Firebase Console](https://console.firebase.google.com/)
2. Click "Add project"
3. Enter project name: `twinship` (or your preferred name)
4. **Optional**: Enable Google Analytics (recommended for production)
5. Click "Create project"

### Step 2: Add Apps to Project

#### iOS App:
1. In Firebase Console, click "Add app" → iOS
2. Bundle ID: Get from `app.json` → `expo.ios.bundleIdentifier` (default: `com.ashleygray.vibecode`)
3. Download `GoogleService-Info.plist`
4. **DO NOT** add this file to the repo - it will be generated by Expo

#### Android App:
1. Click "Add app" → Android
2. Package name: Get from `app.json` → `expo.android.package` (default: `com.ashleygray.vibecode`)
3. Download `google-services.json`
4. **DO NOT** add this file to the repo - it will be generated by Expo

### Step 3: Enable Authentication

1. In Firebase Console, go to "Authentication" → "Sign-in method"
2. Enable "Email/Password" provider
3. **DO NOT** enable "Email link (passwordless sign-in)" yet (Phase 2)
4. Save

### Step 4: Create Firestore Database

1. Go to "Firestore Database" → "Create database"
2. Choose "Start in production mode" (we'll deploy custom rules)
3. Select your preferred location (e.g., `us-central1`)
4. Click "Enable"

## Environment Configuration

### Step 1: Get Firebase Config

1. In Firebase Console, go to "Project Settings" (gear icon)
2. Scroll down to "Your apps"
3. Select the web app config (or create web app if needed)
4. Copy the config values

### Step 2: Update `.env` File

Create or update `.env` file in project root:

```bash
# Firebase Configuration
EXPO_PUBLIC_FIREBASE_API_KEY=your_api_key_here
EXPO_PUBLIC_FIREBASE_AUTH_DOMAIN=your_project.firebaseapp.com
EXPO_PUBLIC_FIREBASE_PROJECT_ID=your_project_id
EXPO_PUBLIC_FIREBASE_STORAGE_BUCKET=your_project.appspot.com
EXPO_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=your_sender_id
EXPO_PUBLIC_FIREBASE_APP_ID=your_app_id
EXPO_PUBLIC_FIREBASE_MEASUREMENT_ID=your_measurement_id  # Optional
```

**IMPORTANT**:
- **NEVER commit `.env`** to version control
- Use `.env.example` as a template
- Share values securely with team members

### Step 3: Verify Configuration

Run the app to verify Firebase initializes:

```bash
npm start
```

Look for these log messages:
```
📦 Initialized new Firebase app
✅ Firestore initialized
✅ Firebase initialized successfully
```

## Switching from Stub to Production

The project currently uses stubbed Firebase Auth for Expo Go compatibility. To enable production auth:

### Option 1: Environment Detection (Recommended)

1. Create `src/services/firebase/auth.ts` that switches between stub and production:

```typescript
import { Platform } from 'react-native';
import Constants from 'expo-constants';

// Check if running in Expo Go
const isExpoGo = Constants.appOwnership === 'expo';

// Export the appropriate service
export * from isExpoGo
  ? './auth.stub'
  : './auth.production';
```

2. Rename current `auth.ts` to `auth.stub.ts`
3. Use `auth.production.ts` for development builds

### Option 2: Manual Switch (Simple)

1. Rename `src/services/firebase/auth.ts` to `auth.stub.ts`
2. Rename `src/services/firebase/auth.production.ts` to `auth.ts`
3. Build development build:

```bash
# iOS
npx expo run:ios

# Android
npx expo run:android
```

**Note**: After switching, you MUST create a development build. Firebase Auth will not work in Expo Go.

## Security Rules Deployment

### Step 1: Install Firebase CLI

```bash
npm install -g firebase-tools
firebase login
```

### Step 2: Initialize Firebase Project

In project root:

```bash
firebase init
```

Select:
- ✅ Firestore (rules and indexes)
- ❌ Functions, Hosting, etc. (not needed yet)

When prompted:
- Use existing project: Select your Firebase project
- Firestore rules file: `firestore.rules` (already exists)
- Firestore indexes file: `firestore.indexes.json` (will create next)

### Step 3: Deploy Security Rules

```bash
firebase deploy --only firestore:rules
```

Verify deployment:
```
✔ Deploy complete!
```

### Step 4: Test Security Rules

1. Go to Firebase Console → Firestore → Rules
2. Click "Rules Playground"
3. Test scenarios:

```javascript
// Should ALLOW:
// - User reading their own profile: /users/{their_uid}
// - Twin pair member reading stories: /twinPairs/{pairId}/stories/{storyId}

// Should DENY:
// - User reading another user's profile
// - Non-member reading twin pair data
```

## Firestore Indexes

### Required Composite Indexes

Create `firestore.indexes.json`:

```json
{
  "indexes": [
    {
      "collectionGroup": "stories",
      "queryScope": "COLLECTION",
      "fields": [
        { "fieldPath": "isDeleted", "order": "ASCENDING" },
        { "fieldPath": "updatedAt", "order": "DESCENDING" }
      ]
    },
    {
      "collectionGroup": "alerts",
      "queryScope": "COLLECTION",
      "fields": [
        { "fieldPath": "recipientId", "order": "ASCENDING" },
        { "fieldPath": "isDeleted", "order": "ASCENDING" },
        { "fieldPath": "sentAt", "order": "DESCENDING" }
      ]
    },
    {
      "collectionGroup": "alerts",
      "queryScope": "COLLECTION",
      "fields": [
        { "fieldPath": "expiresAt", "order": "ASCENDING" }
      ]
    },
    {
      "collectionGroup": "games",
      "queryScope": "COLLECTION",
      "fields": [
        { "fieldPath": "userId", "order": "ASCENDING" },
        { "fieldPath": "gameType", "order": "ASCENDING" },
        { "fieldPath": "completedAt", "order": "DESCENDING" }
      ]
    },
    {
      "collectionGroup": "games",
      "queryScope": "COLLECTION",
      "fields": [
        { "fieldPath": "gameType", "order": "ASCENDING" },
        { "fieldPath": "completedAt", "order": "DESCENDING" }
      ]
    }
  ],
  "fieldOverrides": []
}
```

### Deploy Indexes

```bash
firebase deploy --only firestore:indexes
```

**Note**: Index creation can take several minutes. Monitor progress in Firebase Console.

## Testing the Setup

### 1. Test Authentication

```typescript
// In your app
import { firebaseAuthService } from '@/services/firebase/auth';

// Sign up test user
const result = await firebaseAuthService.signUp(
  'test@example.com',
  'testPassword123',
  {
    name: 'Test User',
    birthdate: '1990-01-01',
    twinType: 'identical',
    accentColor: 'celestial-indigo'
  }
);

console.log('Sign up result:', result);
// Should log: { success: true, user: {...}, profile: {...} }
```

Verify in Firebase Console:
- Authentication → Users: User should appear
- Firestore → users/{userId}: Profile document should exist

### 2. Test Firestore Operations

```typescript
import { firestoreService } from '@/services/firebase/firestore';
import { getUserPath } from '@/models/firebase/collections';

// Create test document
await firestoreService.createDocument(
  getUserPath('test-user-id'),
  'test-user-id',
  { name: 'Test', email: 'test@example.com' }
);

// Read test document
const doc = await firestoreService.getDocument(
  getUserPath('test-user-id'),
  'test-user-id'
);

console.log('Document:', doc);
```

### 3. Test Offline Queue

```typescript
import { offlineQueueService } from '@/services/firebase/offlineQueue';
import { useSyncStore } from '@/state/syncStore';

// Initialize offline queue
offlineQueueService.init();

// Simulate offline operation
```

## Monitoring & Maintenance

### Daily Monitoring

1. **Firebase Console → Authentication**: Check user growth
2. **Firestore → Usage**: Monitor read/write counts
3. **Firestore → Data**: Spot-check data integrity

### Weekly Maintenance

1. **Review Security Rules**: Ensure no unauthorized access
2. **Check Indexes**: Verify indexes are used (query performance)
3. **Monitor Costs**: Firebase Console → Usage and billing

### Monthly Review

1. **Audit Failed Operations**: Check `syncStore` for persistent failures
2. **Review Error Logs**: Check for recurring Firebase errors
3. **Optimize Queries**: Identify and optimize expensive queries

### Cost Optimization

**Free Tier Limits (Spark Plan):**
- Firestore: 50K reads/day, 20K writes/day, 1GB storage
- Auth: Unlimited (email/password)
- Functions: Not using yet

**Optimization Tips:**
1. **Cache Firestore Reads**: Use Firestore local cache
2. **Batch Operations**: Group multiple writes into batches
3. **Limit Listeners**: Unsubscribe from real-time listeners when not needed
4. **Paginate Queries**: Load data in chunks (e.g., 20 stories at a time)

## Troubleshooting

### Issue: "Firebase Auth is temporarily disabled"

**Cause**: Using stubbed auth service
**Solution**: Switch to production auth and create development build

### Issue: "Permission denied" errors in Firestore

**Cause**: Security rules not deployed or user not authenticated
**Solution**:
1. Deploy security rules: `firebase deploy --only firestore:rules`
2. Verify user is signed in: `firebaseAuthService.getCurrentUser()`

### Issue: "Index not found" errors

**Cause**: Required composite indexes not created
**Solution**:
1. Check Firebase Console error message for index link
2. Click link to create index automatically, or
3. Deploy indexes: `firebase deploy --only firestore:indexes`

### Issue: Offline queue not processing

**Cause**: Network listener not initialized or processing stuck
**Solution**:
1. Check network status: `useSyncStore.getState().isOnline`
2. Manually trigger: `offlineQueueService.processQueue()`
3. Clear stuck operations: `offlineQueueService.clearAllOperations()`

### Issue: High Firestore costs

**Cause**: Too many reads (real-time listeners or excessive queries)
**Solution**:
1. Check Firestore usage dashboard
2. Unsubscribe from listeners when screens unmount
3. Implement pagination for large collections
4. Use Firestore local cache

### Issue: Encryption key not found

**Cause**: User signed in but encryption key not stored
**Solution**:
1. User must sign in again (key derived from password)
2. Check SecureStore availability
3. Verify `EncryptionService.deriveKeyFromPassword()` is called on sign-in
